## 1. 这是什么：一句话概括

**DDI 是加拿大国防部（DND）联合国防投资局（DIA）建立的一个"持续滚动、预审资格制"的无人/自主系统供应商采购平台**，目的是绕开传统"一次性招标"的漫长周期，用一个常开常新的**预审合格供应商池**，让加拿大军方（CAF）和**加拿大海岸警卫队（CCG）**能够快速对接、快速采购新兴无人机与自主系统技术 `[S1]`。

::: danger 容易被忽略的一点：服务对象不止 CAF
官方新闻稿明确写的是 **"for the Canadian Armed Forces (CAF) and the Canadian Coast Guard (CCG)"** `[S1]`。这一点在 CGAI 的分析文章 `[S4]` 中**完全没有提到**——该文章全文只讲 CAF，只字未提海岸警卫队。如果贵司未来考虑海事/沿海应用场景，CCG 这条线不能只看这篇文章，要以官方新闻稿为准。
:::

## 3. 运作机制：RFSA 供应商资格池

DDI 的核心工具是一个 **RFSA（Request for Supply Arrangement，供应安排请求）**，不是传统意义上的"招标合同"。

::: tip 和传统招标的本质区别
| | 传统招标（RFP） | RFSA 供应商池 |
|---|---|---|
| 竞争方式 | 打分竞争 | **及格/不及格**制 `[S4]` |
| 中标后果 | 直接授予合同 | 只**获得竞标资格**，不保证合同 `[S1]` `[S2]` |
| 开放频率 | 单次 | 首年每3个月、此后每6个月一轮，至2031年7月 `[S4]` `[S7]` `[S8]` |
| 技术方案 | 每项目需详细方案 | 仅需证明满足资格门槛 `[S4]` |
:::

## 8. 机会分析：两种公司画像分别怎么看 DDI

无人机相关公司大致分两类背景，DDI 对它们的机会点和参与方式并不一样，分开讨论：

- **画像一**：纯 AI + SaaS 技术背景，自己不造机体，用无人机采集的数据做 Wildfire AI（火点/烟雾识别、态势感知、决策支持）
- **画像二**：无人机研发制造公司，有完整机体、载荷、系统集成能力（如 [消防侦察无人机原型机技术需求规格](./firefighting-prototype-requirement.md)）

### 8.1 画像一：纯 AI + SaaS 技术背景公司

#### 能不能注册？——能

DDI 的资格门槛只看两件事：**是不是"加拿大公司"**（`Buy Canadian` 定义，含跨国公司的加拿大子公司）和**是否通过 CanadaBuys 完成注册** `[S4]`；官方新闻稿明确说明既往国防经验不是必要条件，评估依据是技术能力、安全就绪度、满足运营需求的能力 `[S1]`。这些条件里**没有一条要求申请人必须自己制造硬件**。一家只做感知算法、数据平台、云端分析的公司，只要是加拿大注册实体，理论上和硬件厂商一样有资格申请。

#### 最佳切入赛道

| DDI 赛道（官方原文）`[S2]` `[S3]` | 匹配度 | 理由 |
|---|---|---|
| communications and data systems（通信与数据系统） | 🟢 高 | 官方原句本身就包含"data systems supporting autonomous platforms"这类表述所指向的能力——AI感知、数据架构、指挥控制软件正是这条赛道的核心 |
| innovation and experimentation activities（创新与实验） | 🟢 高 | 官方定位为"专为尚不具备成熟商用产品的早期公司设计" `[S4]`，对早期SaaS公司是天然的低门槛入口 |
| engineering and integration services（系统集成） | 🟡 中 | 若能证明"把AI感知模块集成进第三方无人机平台"的工程能力，也可申请这条 |
| Uncrewed and Autonomous Systems（UxS，整机/组件） | 🔴 低 | 官方原句里这条针对的是系统本体，纯软件公司不具备"完整系统"资质，除非以组件供应商身份和硬件商组队 |

#### 现实的参与路径：大概率是"配套"而不是"主角"

RFSA 的运作机制是：申请人先进入预审合格池，"操作需求出现后，Defence Team 向已获资格的供应商发出定向需求，供应商再就具体项目竞争" `[S4]`。这意味着：

- 如果未来某个定向需求是"**采购一整套战术ISR无人机**"，纯软件公司**单独投不了**，因为交付物包含机体。
- 如果定向需求是"**为现有无人机机队提供火点识别/态势感知AI能力**"或"**数据架构与指挥控制软件**"，纯软件公司完全可以**作为主承包商直接投标**。
- 更常见的情况是**组队（teaming）**：软件公司作为分包商/技术供应商，挂靠在一家已在 UxS 赛道注册的硬件 OEM 名下联合投标——这是国防采购里非常标准的操作模式，不是退而求其次。

#### 需要提前准备的门槛

::: warning 软件/数据类供应商的隐性门槛
"communications and data systems"这条赛道天然涉及国防数据处理，实际定向需求出现时大概率会要求达到一定的**网络安全与数据主权等级**（例如 PBMM 一类的政府云安全评估、区域数据驻留、KMS密钥管理）。这些不是注册资格的门槛，但会是后续具体项目竞标时的硬性要求，建议在准备申报材料阶段就把现有的数据安全架构文档化，而不是等到中标后才补。
:::

#### 行动建议（画像一）

1. **现在注册**：以"通信与数据系统"和"创新与实验"两条赛道为主申请，不必等有硬件产品才动手。
2. **准备好"能力证据"而非"产品清单"**：申报材料重点展示算法性能指标（如检测准确率、推理延迟）、数据架构、安全合规能力，而不是机体规格。
3. **主动寻找硬件 OEM 组队对象**：提前接触已有/计划注册 UxS 赛道的加拿大无人机制造商，为未来"整机类"定向需求做联合投标准备。
4. **留意"数字使能"相关的具体项目动向**：这类需求最可能不需要机体交付，是纯软件公司胜率最高的战场。

### 8.2 画像二：无人机研发制造公司

结合现有消防侦察无人机原型机已定义的产品能力，逐条对照 DDI 的赛道与用例：

#### 匹配度速览

| DDI 赛道 / 用例 | 现有能力（简述） | 匹配度 |
|---|---|---|
| 用例1：低成本战术ISR无人机 | LWIR+EO+激光测距 ISR 平台 | 🟢 高 |
| 赛道：通信与数据系统 | 边缘AI推理、遥测、地理参考引擎 | 🟢 高 |
| 赛道：测试与训练 | Hinton GRID 实测经验（民用场景） | 🟡 中 |
| 赛道：创新与实验 | 产品仍处 v1.0 原型阶段 | 🟢 高 |
| 用例2：复杂地形UGV | 无地面车辆产品线 | 🔴 低 |
| 用例3：海事自主系统 | 无海事产品线 | 🔴 低 |
| 用例4：标准化爆炸载荷 | 与民用消防定位冲突 | 🔴 不建议 |
| 用例5：反无人机拦截器 | 有探测技术基础，无拦截产品线 | 🟡 中低 |
| 用例6：深度精确打击 | 无相关性，且未获采购批准 | 🔴 不适用 |

#### 详细说明

- **用例1（🟢 高）**：现有原型机本身就是 LWIR+EO+激光测距 ISR 平台（对应技术需求 HW-PL-001~007）。需要一个"低成本"精简变体——政府版基线吊舱 Workswell Wiris Pro Sc 定价 CAD 25–35k 偏贵，可能需要用性能相近但走非中国供应链的替代方案重新做成本优化。
- **通信与数据系统赛道（🟢 高）**：Jetson Orin NX 边缘AI推理、MQTT遥测、地理参考引擎、火点坐标MAVLink自定义消息（对应 SW-FC-006、SW-AC-*）。这条恰好是公司真正的技术护城河，比机体制造本身更有差异化价值。
- **测试与训练赛道（🟡 中）**：已有 Hinton GRID Testing 实测经验（Alberta Wildfire 认可的IR供应商评估，对应 AI-007）。但 Hinton GRID 是民用消防场景，能否直接作为国防测试评估资格证据，需要在申请材料里主动论证，不会自动被认可。
- **创新与实验赛道（🟢 高）**：产品目前是 v1.0 Draft 原型阶段，尚未量产商用。官方说明这条赛道"专为尚不具备成熟商用产品的早期公司设计" `[S4]`——很可能是**最现实的第一入口赛道**，门槛比直接申请完整 UxS 赛道低。
- **用例2 UGV（🔴 低）**：无地面车辆产品线，除非战略性决定跨界，不建议作为切入点。
- **用例3 海事系统（🔴 低）**：目前无海事产品线；但 CCG 也是 DDI 服务对象之一 `[S1]`，若未来往 BC 海岸线消防/沿海监视方向延伸，可关注。
- **用例4 爆炸载荷（🔴 不建议）**：涉及军用弹药载荷，与公司民用消防定位冲突，需认真评估是否符合公司业务方向和出口管制合规成本。
- **用例5 反无人机拦截器（🟡 中低）**：有 DAA/避障技术基础（LiDAR、RealSense立体视觉，对应 HW-DAA-*），探测识别部分有复用可能，但"拦截"是完全不同的产品线，需要新研发投入。
- **用例6 深度精确打击（🔴 不适用）**：无相关性，且官方明确尚未批准采购，不是当前商业机会。

#### 一个容易被忽略的战略优势

::: tip 已经在按"国防级供应链标准"做事，只是没意识到
现有原型机的技术需求文档已写死一整套**非中国供应链约束**（SYS-012）：KDE Direct（美）电机、Microhard（加）通信链路、Workswell（捷克）/Teledyne FLIR（美）吊舱、Septentrio（比利时）GNSS、Ouster（美）LiDAR——这套"政府版"供应链策略，恰好和 DDI 反复强调的"主权供应链、可信盟友来源"高度一致 `[S1]` `[S4]`。

不需要为了投 DDI 重新设计供应链，现有的 PIN 2025-03 合规策略本身就是一份现成的"安全就绪度（security readiness）"证据，可以直接写进申报材料。
:::

#### 行动建议（画像二）

1. **现在就注册**：不要等下一轮公告发布才开始，去 CanadaBuys / SAP Business Network Discovery 注册账号，填完 Government of Canada 供应商资料，这个准备过程本身需要时间 `[S3]`。
2. **优先申请"创新与实验"赛道**：门槛最低、专为早期公司设计 `[S4]`，且当前产品阶段（v1.0 Draft）最匹配。
3. **同时申请"通信与数据系统"赛道**：这是真正的技术差异化所在。
4. **申报材料里主动引用 Hinton GRID Testing 经历**，作为"testing and training"赛道的能力佐证。
5. **申报材料里主动引用 SYS-012 非中国供应链策略**，作为"安全就绪度"证据。
6. **不要在任何对外材料里引用 $5000 拦截器价格**，除非拿到独立官方文件佐证。
7. **持续监控** CanadaBuys 该条目的 Event Messages 板块，留意下一轮开放日期，以及可能补发的说明会官方讲义。
